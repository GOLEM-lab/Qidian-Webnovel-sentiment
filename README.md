# Echoes of Emotion

**Linking Narrative and Reader Response of Web Novels in Chinese and English**

Code and data for the JCLS 2026 paper. The study tests whether the emotional
valence of a narrative shapes the valence of the comments readers leave on it,
and whether that relationship holds across languages and platforms. It extends
Pianzola, Rebora and Lauer (2020), *Wattpad as a resource for literary
studies*, [PLOS ONE 15(1): e0226708](https://doi.org/10.1371/journal.pone.0226708)
— which reported a positive paragraph-level association on Wattpad.
This study covers a parallel Chinese/English corpus, and adds statistical analysis
with Generalized Additive Models, so the association between story and comments is free to change shape as a story unfolds.

The corpus is 107 web novels published in Chinese on **Qidian** and in English
translation on **WebNovel**, restricted to the freely readable opening chapters
of each (on average the first 3.6% of a book). Reader comments are anchored to
individual paragraphs on both platforms, so narrative sentiment and reader
sentiment can be compared at the same granularity.

is stored in Git LFS. GitHub's "Source code (zip)" archive does _not_ contain

This affects the GitHub release zip/tar.gz **and** a plain `git clone` on a

1. **Release assets.** The CSV is attached directly to the
   [latest release](../../releases/latest) as a downloadable asset. Release
   assets are stored outside LFS and need no special tooling. *(Recommended.)*

   ```bash

   git clone https://github.com/GOLEM-lab/Qidian-Webnovel-sentiment.git
   ```
   If you have already cloned without LFS, run `git lfs install && git lfs pull`.

To check what you ended up with: the real file is ~208 MB with 552,857 lines; a
pointer is 134 bytes with 3 lines.

### Paragraph and comment text — restricted access

This repository holds **derived measures only**: sentiment scores and positional
metadata, one row per paragraph per platform. It does not contain the paragraphs
themselves, the text of the comments, or any other novel content, which remain
subject to the platforms' copyright and terms of use.

Those texts belong to the Qidian-WebNovel Corpus (Yu et al., 2025) — 110 novels
in Chinese and English together with their book-, chapter- and paragraph-level
reader comments — deposited on DataverseNL under **restricted access**:

> Qidian-Webnovel Corpus 110. DataverseNL.
> [doi:10.34894/GQXX3K](https://doi.org/10.34894/GQXX3K)

Access is granted on request through that record, under the terms stated there.
If you obtain it, the `bookId`, `chapterId_qidian`, `chapterId_webnovel` and
`paragraphId` columns documented below are the keys for joining the text back
onto these sentiment scores.

## The dataset

One row per paragraph **per platform**, so every paragraph appears twice:
552,856 rows = 2 × 276,428 paragraphs. `source` distinguishes the two platforms.
188,239 rows have a comment and are used in the statistical models.

| column | meaning |
|---|---|
| `bookId` | book identifier, stable across platforms |
| `source` | `Qidian` (Chinese) or `WebNovel` (English) |
| `new_index` | paragraph position within the book |
| `chapter_index` | chapter rank among *aligned* chapters |
| `chapter_position` | true chapter position in the book |
| `paragraph_index` | paragraph position within its chapter |
| `percentage_index` | position in the whole book, as a percentage |
| `percentage_index_rank` | earlier definition, kept for comparison |
| `percentage_free_chapters` | how much of the book the free sample covers |
| `par_valence` | paragraph sentiment, `p_pos − p_neg`, in [−1, 1] |
| `par_sentiment`, `par_p_neg/neu/pos` | predicted label and class probabilities |
| `avg_comm_valence` | mean valence of comments on that paragraph |
| `comm_count` | number of comments on that paragraph |
| `comm_anchor` | **share of those comments whose paragraph anchor is exact** (see below) |
| `chap_avg_comm_valence`, `chap_comm_count` | the same, aggregated per chapter |
| `par_valence_roll_11/51` | rolling means over 11 / 51 paragraphs |
| `par_valence_trend`, `par_valence_detrended` | book-length trend and residual |
| `zh_missing`, `zh_status`, `len_dev`, `zh_author_note` | segmentation quality flags |

### `comm_anchor` — read this before modelling the Qidian side

Qidian records a comment's position as an index into Qidian's *own* paragraph
division, while the corpus re-segments the Chinese text to match the English
paragraph structure. The two indices are not interchangeable, so the link was
reconstructed.

For the 58 books that preserve the publisher's full-width indentation, those
indents mark Qidian's real paragraph boundaries and the mapping is exact. The
other 49 books were scraped as a single unbroken string in which no paragraph
boundary is present; there the anchor is placed proportionally, with a median
error of 0 paragraphs and 83.7% of anchors within one paragraph (estimated by reading the paragraph content).

`comm_anchor` is the share of a paragraph's comments placed by the exact
method — 1 throughout the WebNovel side, 1 or 0 for most Qidian paragraphs, and
fractional for the ~2,100 where a chapter mixes both. **Filter on
`comm_anchor == 1` for any analysis that needs an exact link**, and use it as a
robustness split: the paper reports that the Qidian interaction weakens from
p = .006 to p = .086 on the exactly anchored subset.

## Reproducing the analysis

### 1. Sentiment inference

Two models, matched to the two text types:

| texts | model | max length |
|---|---|---|
| reader comments | [`fpianz/sentiment-webnovel-comments-xlmr-en-zh`](https://huggingface.co/fpianz/sentiment-webnovel-comments-xlmr-en-zh) (fine-tuned) | 256 |
| story paragraphs | [`cardiffnlp/twitter-xlm-roberta-base-sentiment`](https://huggingface.co/cardiffnlp/twitter-xlm-roberta-base-sentiment) (zero-shot) | 128 |

Both are multilingual, so Chinese and English are scored by the same model and
the two sides stay comparable. Each input CSV is scored in place, gaining
`sentiment`, `valence`, `p_neg`, `p_neu`, `p_pos`.

```bash
pip install -r scripts/requirements.txt
sbatch scripts/main_job.sh          # or run run_inference_webnovel.py directly
```

The job expects the four input files (Qidian/WebNovel × comments/paragraphs) in
its `--data_dir`; edit `PROJECT_DIR` in `main_job.sh` for your cluster. On one
A100 the full 3.6M texts take well under the 4-hour wall clock.

### 2. Statistical analysis

```bash
mkdir -p logs && sbatch GAM/gam_job.sh
```

`GAM_analysis_habrok.R` runs end to end in ~16 minutes on 8 cores: the nested
model build-up, the final model, four sensitivity fits, diagnostics, a linear
mixed-model comparison, and every figure. It reads the CSV above and writes
models to `GAM/` and figures to `figures/`.

The final model is

```r
avg_comm_valence ~ source
  + s(par_valence, by = source, k = 20)
  + s(percentage_index, by = source)
  + ti(par_valence, percentage_index, by = source)
  + s(percentage_index, bookId, bs = "fs", m = 1)
  + s(bookId, par_valence, bs = "re")
```

fitted with `mgcv::bam`, `log1p(comm_count)` precision weights and an AR(1)
residual term. The `ti()` interaction is the research question — does the
paragraph→comment coupling change as a story progresses — and is retained in
every model rather than being subjected to a selection step.

`GAM_Model_Comparison.pdf` reports the results, including the concurvity
diagnostics that bound how far individual smooth terms can be interpreted.
